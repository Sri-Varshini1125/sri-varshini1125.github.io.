    Features

    Everything runs on classic data structures taught in DSA.

    🌲

    Trie (Prefix Tree)

    Words share common prefixes, so finding every completion of a prefix never scans the whole dataset.

    🔝

    Top-k with Min-Heap

    A heap of size k keeps only the most frequent matches, giving ranked results in O(M log k).

    🧠

    Learns from You

    Every selection increases that entry's frequency, so suggestions adapt to real usage.

    How it Works

    From keystroke to ranked suggestions in four steps.

    1
    Build the Trie

    Each word is inserted character by character. The last node of a word stores its frequency.

    2
    Walk the prefix

    As you type, the engine follows the prefix down the tree in O(L) steps, where L is the prefix length.

    3
    Collect and rank

    A DFS visits all words below that node and feeds them to a min-heap that keeps the top k by frequency.

    4
    Learn

    When you pick a suggestion, its frequency is incremented, so future results are ranked better.

    Complexity Analysis

    N = number of words, L = prefix length, k = suggestions shown.

    ApproachLookupInsertSpace
    Linear scan of a listO(N · L)O(1)O(N)
    Sorted array + binary searchO(L log N + k)O(N)O(N)
    Trie + min-heap (this project)O(L + k)O(L)O(N · L) worst case

    Trade-off: a trie uses more memory than a flat list, but gives far faster lookups as the dataset grows.

    About the Project

    This is a DSA capstone project that demonstrates how the right data structure turns a slow search into an instant one.

    Problem

    Scanning every record for each keystroke is too slow for large datasets.

    Solution

    Store data in a Trie and rank matches with a min-heap for fast, relevant suggestions.

    Tech

    Core logic designed in C (Trie, Heap); web interface in HTML, CSS and JavaScript.

    Future Scope

    Typo correction with edit distance, LRU caching, and a C server backend.
